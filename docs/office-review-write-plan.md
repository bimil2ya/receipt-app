# 사무실 검토기록 입력 단계(P2) 설계

작성일: 2026-09-30
상태: 구현 전 검토용. 배포와 기존 Drive 자료 변경은 이 문서 범위 밖이다.

## 목표

사무실 담당자가 팀별 제출 자료를 대조한 뒤, 공식 월별 전체집계 Google Sheet의 검토기록에 결과를 남긴다. 현장 앱은 선택된 팀의 기록만 읽어 표시하고, 사용자가 수정 또는 추가 자료를 제출하면 수정 버전과 연결 자료로 후속 대조가 가능해야 한다.

## 확인된 사실

1. 월별 `전체집계_YYYY년 MM월` Google Sheet에는 `검토기록` 탭이 있고, 자동 갱신 열과 담당자 입력 열이 분리되어 있다.
2. 담당자 입력 열은 `검토 상태`, `담당자 메모`, `추가 자료 요청`, `검토 담당자`, `검토 시각`이다. **같은 월을 재집계할 때** 안정적인 영수증 식별값으로 이 다섯 열을 보존한다. 다음 달 자료로 자동 이월하지는 않는다.
3. 팀 앱은 `/api/review`에서 선택 팀의 기록만 읽는다. 월 폴더·집계 Sheet·탭·필수 열·Drive 위치와 버전을 확인하지 못하면 빈 기록 성공으로 바꾸지 않고 오류를 표시한다.
4. 대시보드는 현재 Drive 자료를 읽기만 하며, `staff`와 `owner` 패스프레이즈 역할을 구분한다. 개인별 사무실 담당자 식별 또는 검토 변경 감사 원장은 아직 없다.
5. 현장 팀은 로그인 대신 팀 이름과 해당 기기의 등록 사용자 이름을 사용한다. 이 방식은 강한 접근 통제나 열람자 추적을 보장하지 않는다.

## 현재 가능한 업무 흐름

```mermaid
flowchart LR
  A[현장 팀 제출] --> B[월 전체집계 Sheet]
  B --> C[사무실 담당자가 검토기록 열 입력]
  C --> D[팀 앱의 팀별 검토기록 조회]
  D --> E[수정 또는 추가 자료]
  E --> A
```

이 흐름에서는 Google Sheet 공유 권한이 사무실 담당자만 수정 가능하도록 설정되어야 한다. 앱 코드가 그 권한을 대신 보장하지는 않는다.

## 미확인 정책

아래는 업무 규칙이므로 현재 코드의 상수나 자동 상태 전환으로 고정하지 않는다.

| 항목 | 필요한 결정 | 안전한 기본값 |
| --- | --- | --- |
| 사무실 입력자 | 자유 입력인지, 사무실 명단 선택인지 | 선택 명단을 설정으로 주입하고, 미설정이면 기존 Sheet 직접 입력만 허용 |
| 상태값 | 승인·보완 요청·반려 등의 공식 의미와 전이 | 자유 입력 메모로 보존하며 앱이 완료·승인을 자동 선언하지 않음 |
| 대시보드 쓰기 | 직접 편집을 허용할 역할과 대상 월 | 읽기 전용 유지 |
| 동시 수정 | 담당자 두 명 또는 Sheet 직접 편집과 대시보드 편집이 겹칠 때 | 버전 불일치면 저장하지 않고 다시 읽도록 중단 |
| 감사 | 변경 전후 값, 입력자, 기기·시각의 보관 기간 | 기존 Sheet의 `검토 담당자`·`검토 시각`만 보존, 별도 감사 원장은 만들지 않음 |

## 구현 후보와 경계

### P2-A: 현재 Sheet 직접 입력 흐름의 검증

1. 담당자 입력 다섯 열만 같은 월의 다음 재집계에 보존되는지 테스트한다.
2. 팀 앱에서 같은 팀의 상태·메모·요청·담당자·시각이 표시되고 다른 팀은 제외되는지 확인한다.
3. 연결된 추가 자료와 수정 버전이 검토 행에 보이는지 확인한다.

이 범위는 현재 구현되어 있으며, Drive 계정에서 실제 Sheet를 수정하는 운영 검증만 남아 있다.

### P2-B: 대시보드 직접 입력(정책 확정 뒤에만)

새 API 또는 Drive 쓰기를 만들기 전에 다음 계약을 확정한다.

1. 실제 사무실 구성원을 판별하는 수단. 현재 `staff`/`owner`는 개인 식별 없는 공유 역할 토큰이므로, 역할만으로 사무실 담당자만 수정할 수 있다고 보장할 수 없다. Google 계정 기반 확인·Sheet ACL 연동 또는 공유 자격증명 사용 위험의 명시적 수용을 먼저 결정한다.
2. 쓰기 허용 역할과 사무실 입력자 명단의 설정 위치.
3. Google Sheets API 권한과 전용 테스트 Sheet. 현재 Drive OAuth가 Sheets 쓰기를 허용하는지는 확인되지 않았다.
4. 영수증 식별값·수정 버전·Sheet 파일 ID·파일 version을 요청에 포함한다. 서버는 읽기 전후 값이 동일할 때만 담당자 입력 다섯 열을 바꾼다.
5. 실패·응답 불명·버전 충돌은 성공 표시나 자동 재시도로 바꾸지 않는다. 변경 전후 값을 포함한 감사 기록의 저장 위치와 보존 기간도 먼저 정한다.
6. 현장 앱에는 그 팀의 공개 대상 필드만 내려준다. 팀 이름만 선택하는 현재 방식에서는 강한 비공개를 주장하지 않는다.

## 완료 기준

- 사무실 입력이 같은 월 재집계 후에도 영수증 식별값 기준으로 남는다.
- 팀 앱은 해당 팀 기록만 표시하고, 읽기 실패를 기록 없음이나 검토 완료로 표시하지 않는다.
- 대시보드 직접 쓰기를 도입하는 경우에는 역할·입력자·동시 수정·감사 정책과 실제 Sheets 권한을 검증한 뒤에만 구현한다.
